# 專案脈絡

目標是讓下一個 agent 接續工作，不必重建已確認的背景。跨案理解與個人偏好依你 vault 的
`ROUTING.md` 管理；本 skill 只維護目前有寫入授權的 repo。

## 接手

先遵循 repo 的 AGENTS.md／CLAUDE.md，再讀它指向的脈絡文件；沒有指向時，尋找
`docs/PROJECT_CONTEXT.md`、`PROJECT_CONTEXT.md`、`docs/CONTEXT.md` 或 README。
配合 Git 狀態、相關修改與產物確認現況，不把舊 worktree 或一份歷史摘要當目前狀態。
簡單且自足的問題不需要整套盤點；讀取深度以這次任務需要為準。

## 更新

「只看／評估／不修改」時只讀，即使找不到文件也不新建。
已授權的實作或文件整理，若產生會影響接手的新決策、已驗證陷阱、驗收結果或關鍵待辦，
在收尾時更新既有脈絡文件。沒有這類新資訊就 no-op，不建立每次工作流水帳。

寫入至少能回答：
- 決定或改變了什麼，原因及適用範圍是什麼？
- 證據來自哪個日期、commit、artifact 或人類明確確認？
- 已完成到哪一層：實作、測試、提交、合併、部署、人工接受？
- 下一個工作者需要確認什麼，或從哪裡接續？

優先更新現有區段，詳細執行紀錄連回 repo 的 log／manifest，不抄成第二份。
確有必要且在授權範圍內才新建 `docs/PROJECT_CONTEXT.md`；內容以目前狀態、重要決策、已驗證陷阱、下一步四部分即可。
不複製能從 code 直接得到的整套 API／資料模型清單。

## 範圍與透明度

單案偏好留在 case，跨案偏好的候選與確認依 vault 的 `03-wiki/memory-metabolism.md` 規範；
不自行把學習加進全域 AGENTS.md／CLAUDE.md，也不將永久偏好複製到各平台 auto memory。
平台自有記憶的寫入權限由該平台規則決定，不能由這支 skill 擴張。
原始機敏內容、憑證與 token 不進脈絡文件。既有他人修改要保留。

回報更新的文件及它保存的新決策；沒有寫入時不用為了「有紀錄」補文件。

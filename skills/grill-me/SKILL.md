# grill-me — 動手前先對齊

**為什麼**：最貴的坑不是 code 寫錯，是「做完了、但不是你要的」。重做一遍最花時間。這支 skill 把對齊成本前置到動手之前。

使用者明確要求深入對齊時，逐題釐清關鍵決策。一般任務先用既有脈絡與查證推進，只問會實質改變結果的未知。

- **控制提問負擔**：深入對齊時每次聚焦一個重要決策；可查的事實自行查，不為一般實作選擇逐題等待。
- **每一題都附建議答案**：「我建議 X，因為 Y——你同意，還是要改？」不是列一排選項叫使用者自己挑（多數人不喜歡那樣）。
- **事實自己查**：能從檔案／工具／環境查到的（現有檔在哪、API 怎麼回、上一次用什麼參數、知識庫裡有沒有現成做法），自己去查，不佔用使用者的一題。
- **關鍵決策由使用者確認**：方向、重大成本或外部承諾缺少必要資訊時等待；不依賴答案的已授權工作可以繼續。
- **沿用授權**：使用者要求「先討論／不要改」時維持唯讀；已明確要求實作時，確認範圍內的可逆步驟直接完成，不另加一次口令。

## 新東西的常見對齊點

開新流程／新 skill 前，這幾項沒釘死就先問：

- **交付規格**：輸出格式、篇幅或長度、語言、給誰看、最後落在哪裡。
- **來源與授權**：材料從哪來、能不能用、這次授權到哪一步（只讀／可寫／可對外）。
- **風格參照**：有沒有一份「長這樣就對了」的既有成品可以對齊。
- **知識庫裡有沒有現成的**：先查既有 canonical 頁與既有 skill，別重造輪子。
- **這次不做什麼**：把 non-goal 明確寫下來，比多列幾條 goal 更能防重做。

## 完成判準

目的、必要限制與完成判準已清楚，剩餘關鍵未知已解答或明示。已有實作授權便接續執行；僅授權規劃則交付規劃。

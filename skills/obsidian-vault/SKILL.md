# 知識沉澱

先讀你 vault 的 `ROUTING.md` 決定位置，再讀該 vault 的入口規則。
這支 skill 負責跨案知識；當次專案的 code、設定、進度與驗收留在 active repo，必要時使用 `project-memory`。

## 何時寫入

尊重本次任務的授權範圍。「評估／只讀／先不要改」只產生建議；檔案不存在也不是新建的理由。
使用者已要求整理或保存時，直接完成範圍內的可逆整理，不重問同一份授權。
沒有新增會改變未來判斷的知識，允許 no-op；一般工具呼叫與日常進度不用逐次沉澱。

## 做法

1. **定位既有理解。** 查相關 index、canonical 頁與 open questions。找到同一概念就更新它，避免另開一份全文。
2. **區分來源與解讀。** 原文存入路由指定的 raw 區，保留原樣；摘要、推論與方法放 wiki。來源含 secret 時，先隔離或去敏，不把值寫入可提交檔案。
3. **限定主張。** 高影響內容寫明來源、觀察日期、適用範圍及 authority。舊決策被取代時標明新舊關係；歷史 review／worklog 保持原樣，在現行頁說明修正。
4. **判斷是否值得抽 skill。** 有重用需求，而且有非顯而易見的判準、可靠腳本或領域資產時，才使用 `forge-skill`。本體位置由 ROUTING 決定，wiki 只留導航。
5. **完成引用。** 更新受影響的索引與 log；只在新增、解答或失效時調整 open questions。檢查本次修改的連結及相互矛盾的入口。

## 回饋與記憶

使用者對當次產物的選擇，先保留該 case 的理由與範圍。單次「好／不好」不自動變成跨案永久偏好。
個人偏好的 canonical 在 ROUTING 指定的 profile；agent 自有記憶只放必要指標，並遵守該平台的寫入授權。
不要因為正在整理知識，就改寫全域 AGENTS.md／CLAUDE.md 或建立第二份永久偏好。

## 完成判準

下個 agent 能找到現行結論、證據與適用範圍，辨認歷史或候選內容，且不需要在兩份全文之間猜哪份有效。
回報改了哪些 canonical 頁、仍有哪些未知；沒有新知識時說明 no-op 即可。

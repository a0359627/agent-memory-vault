# weekly-status

> 這是 `docs/walkthrough-first-skill.md` 走完之後的**完成態**。
> 它刻意很小——一支夠用的第一支 skill 不需要 scripts、references 或 assets，
> 只需要回答六個問題：何時啟用、要什麼輸入、按什麼順序、什麼不能猜、何時停下來問人、什麼算完成。
>
> 內容是虛構的示範，不是可直接上線的流程。拿它當形狀，把內容換成你自己的。

## 什麼時候用

到了每週固定要回報進度的時候，或有人問「這週進展如何」。

## 什麼時候**不要**用

- 季度回顧、結案報告：那要談的是驗收與成效，不是這一週發生什麼。
- 單一問題的回覆（「那個 bug 修好了嗎？」）：直接回答比較快。
- 這一週沒有進度：要寄的是說明，不是硬湊一份報告。

## 輸入

1. 本週的工作軌跡（提交紀錄、工單、會議紀錄，有什麼算什麼）。
2. **上週那份報告**——沒有它就無法對照承諾，這支 skill 就少了一半價值。
3. 已知的外部依賴（在等誰、卡在哪）。

## 步驟

1. **先對照上週承諾。** 上週寫「下週要做」的每一項，這週都要有結論：
   完成／未完成／改期。一項都不能默默消失。
2. **分四段**：本週完成／進行中／卡住的／下週要做。
3. **每一項標來源。** 指不回任何軌跡的項目，標「待確認」，不要寫成已完成。
4. **卡住的每一項都要有負責人。** 沒有負責人就標「待指定」，不要留空。
5. **產出兩個版本**：主管版（不超過五點，只寫決策與風險）與詳細版（全部項目）。
6. **停下來給人看。** 這支 skill 到這裡結束。

## 不能猜的事

- 完成百分比。沒有明確的驗收清單就不寫百分比。
- 卡住的原因在誰身上。看不出來就寫「原因待確認」。
- 下週的交付日期。除非人明確給了日期，只寫「要做什麼」。

## 何時必須停下來問人

- 任何要寄出、發布或通知外部的動作——**一律先停**，產草稿給人看。
- 有項目找不到來源，而它看起來很重要。
- 上週承諾的項目這週完全查不到任何軌跡。

## 完成判準

- 上週承諾的每一項都有結論。
- 四段都在，每一項都能指回來源或標了「待確認」。
- 卡住的每一項都有負責人或「待指定」。
- 主管版不超過五點。
- 兩個版本都是**草稿**，沒有寄出。

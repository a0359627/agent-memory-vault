# weekly-client-report

> 已晉升的活檔（2026-02-03）。晉升理由與門檻見 `03-wiki/skill-weekly-client-report.md`。
> 在真實的 vault 裡，這份會放在 `ROUTING.md` 指定的活檔位置；
> 範例把它放在 `skills-promoted/` 只是為了讓你在同一個資料夾裡看到對照組。

## 什麼時候用

每週要給客戶寫進度報告時。適用所有客戶。

## 什麼時候**不要**用

- 月報或結案報告——那要回顧整段期間並談驗收，不是這支。
- 客戶臨時問「現在到哪了」——直接回答比較快。
- 這一週完全沒有進度——那要寄的是說明，不是報告。硬產一份「本週無進度」只會消耗信任。

## 輸入

1. 該客戶這一週的工時 CSV（從試算表手動匯出）。
2. 上週那份報告（用來對照「上週說要做的」有沒有做）。
3. 本週有無外部事件（客戶請假、等客戶回覆、等第三方）。

## 步驟

1. **解析 CSV。空白欄是 `unknown`，不是 0。**
   同時算出 `unknown` 的筆數，一起帶進報告。這條是被咬出來的，
   細節見 `01-profile/03-known-traps.md` 第 1 條。
2. **對照上週承諾。** 上週寫「下週要做」的每一項，這週都要有結論：完成、未完成、或改期。
   一項都不能默默消失——默默消失才是客戶最記得的那件事。
3. **分四段寫**：本週完成／進行中／卡住的／下週要做。
4. **每一項都要能指回來源**（哪一筆工時、哪一次溝通）。指不回去的就標「待確認」，不要寫進報告。
5. **卡住的那段一定要有負責人。** 卡在客戶就寫「等您回覆 X」；
   卡在我們就寫「我們處理中，預計 X」。卡住而沒有人負責的項目不存在。
6. **`unknown` 的處理**：報告第一行印「本週有 N 筆工時未填」。N 大於 0 時**停下來問人**，
   不要自己決定要不要寫進客戶版。這一題還沒定案，見 `03-wiki/open-questions.md` 的
   `report-unknown-handling`。
7. **輸出草稿檔，結束。** 印出草稿路徑就好。

## 不能猜的事

- 沒填的工時到底做了什麼。標 `unknown`，問人。
- 卡住的原因在誰身上。看不出來就寫「原因待確認」，不要替客戶背鍋，也不要推給客戶。
- 完成度百分比。除非有明確的驗收項目清單，否則不寫百分比。

## 這支 skill **不做**的事

- **不寄信。** 產完草稿就結束。寄送是人的決定，中間一定要有人擋著——
  理由見 `03-wiki/proj-weekly-report-bot.md` 的現行有效段與 known-traps 第 3 條。
- **不美化。** 沒完成就寫沒完成。「快好了」不是一個狀態。
- **不承諾日期。** 下週要做的項目寫「要做什麼」，不寫「哪天交」，除非人明確給了日期。

## 完成判準

- 四段都在，且每一項都能指回來源。
- 上週承諾的每一項都有結論。
- 卡住的每一項都有負責人或明確標「原因待確認」。
- `unknown` 筆數已印出；N 大於 0 時已停下來問過人。
- 草稿寫在 `drafts/`，**沒有寄出**。

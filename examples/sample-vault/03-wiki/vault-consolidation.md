# 定期整併

> **範例說明**：用 bootstrap 建出來的主 vault 本來就有這一頁的完整流程（`03-wiki/vault-consolidation.md`，
> 佔位符已換成你的日期與稱呼）。這裡是小明填完自己的選擇之後的短版：只留**他選了什麼**與流程骨架，
> 步驟細節以你主 vault 裡那份為準。

## 這個 vault 的選擇

- **頻率**：每週五收工前手動跑一次。一人工作室、沒有排程器；寫下來，漏跑一週才看得出來。
- **為什麼從 2026-02-20 開始**：2026-02-18 事故當天有兩個 session 同時在改 [[log]]，第一次出現 log 碎片。
  碎片不併回，log 就不再是完整的劇本。
- **邊界**：只動這個 vault。不碰客戶工作資料夾、不部署、不寄信——
  [[01-preferences]] 那條「會動到外部的動作要有人工核准點」在整併時一樣成立。

## 一輪做什麼

1. **先看報告**（唯讀）：哪些碎片待併、上次以來改最多的頁、Active 超過 60 天的 open question、代謝 warning。
2. **機械整併**（直接做）：碎片依日期原文併回 [[log]]；修目標唯一的壞連結；在 log 記一則標題含「定期整併」的 `lint`。
3. **語意檢查**（只提案）：改任何頁的 `status`、改 `01-profile/`、刪頁、合併兩頁，一律先寫成提案問小明。
4. **沒事就不做**：沒有碎片、沒有可修的連結、沒有提案時，不寫 log，只回一句「本週無需整併」。

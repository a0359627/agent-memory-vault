# Known traps — 反覆咬人的跨切面陷阱

> 這一頁收的是**會再咬你一次**的東西，不是所有 bug。判準：同一個坑踩過兩次，或第一次就
> 花掉半天以上；而且它的症狀是「看起來成功、其實壞了」。
> 版本相關的條目屬條件性實測，使用前在當前環境核對，不據此宣稱新版本仍有或已修復同一問題。

## 條目格式

每條四段，缺一段就還不算一條 trap：

```
N. **一句話症狀（粗體，先講看得到的現象）**
   - **原因**：為什麼會這樣。寫機制，不寫「可能是設定問題」。
   - **驗證**：兩秒內能跑的斷言——什麼指令／什麼查詢，回傳什麼值代表中鏢。
   - **修法**：可以直接貼上去的那一行或那一段。
   - **適用條件**：哪個版本、哪個平台、哪種資料形狀才成立。條件消失時把它移到頁尾的歷史區。
```

按症狀或工具分節；同一族的陷阱放一起，並在節首寫這一族的共同形狀。

## 四條通則（不綁工具，先讀這四條）

這四條不是條目，是判準。它們適用於你之後寫進來的每一條 trap。

1. **「乾跑」必須是零副作用，否則不要叫乾跑。** 會寫入外部系統的東西——寫進下游、建立紀錄、
   觸發外部回呼——都不叫乾跑，叫「少做一步的正式執行」。要嘛做成真的唯讀，要嘛換個誠實的名字；
   因為叫它乾跑，人就會拿它去碰 production。
   *虛構例子*：某個「預覽模式」在算完結果後順手把來源標成「已處理」，於是預覽跑第二次就什麼都看不到了。

2. **多租戶化時，逐一稽核每個「不帶參數」的預設語意——它會靜默反轉。**
   單租戶時「不帶 X」＝「那唯一一個」；加了租戶維度之後，同一支端點變成「全部」，
   而下游服務**不會報錯**，只會開始吃到不屬於它的資料。同理還有「設定繼承全域預設」：
   對危險欄位（webhook 目的地、外部系統位址）要 fail-closed，方便性的繼承（逾時、模型名稱）留著沒關係。
   *虛構例子*：加了租戶欄之後，`GET /items` 從「這個租戶的項目」變成「所有租戶的項目」，
   下游報表安靜地多出別人的資料。

3. **回報要分層：API 200、成功 render 或測試通過只能證明對應層級。**
   （這條的出處是 `AGENT-RULES.md` 的回報分層那一行，不是某個工具的陷阱。）
   實作、測試、提交、合併、部署與人工接受是六件事；HTTP 202 只證明「請求被接受」，
   不證明「工作完成」，更不證明「人類接受」。
   *虛構例子*：批次任務回 202、佇列長度是 0，被當成「跑完了」——實際上是工作根本沒進佇列。

4. **外部系統的「建立時間」不是 immutable key。**
   凡是被排程、審核或發布流程碰過的時間戳都要當**可變欄位**處理：上游會改值的欄位，
   在 upsert 的更新清單裡漏掉一欄，那一欄就凍結在第一次寫入的值，而且全鏈路沒人報錯，
   症狀是下游安靜地全部算錯。
   *虛構例子*：上游會改寫的那個時間欄位沒被列進 upsert 的更新清單，於是本地 DB 永遠留著
   第一次寫入的值，以該欄位為準的任何時間區間統計從此長期偏差——沒有任何一層報錯。

# 01-profile — 有來源、有範圍的個人脈絡

這一層是**結構化偏好的 canonical**：agent 在非瑣碎任務開工前會讀它，所以寫進來的每一條
都會影響未來所有 session 的行為。四個檔各有分工：

| 檔 | 放什麼 |
|---|---|
| `00-who.md` | 你是誰、做什麼、工作語言、canonical 知識庫在哪 |
| `01-preferences.md` | 怎麼跟你合作：語言、決策風格、做事順序、查證邊界 |
| `02-environment.md` | 這台機器的硬限制，每條標觀察日期 |
| `03-known-traps.md` | 反覆咬人的陷阱：症狀 → 原因 → 修法 → 適用條件 |

## 什麼可以直接寫進來

- 你明確說「以後都這樣」或清楚確認過的跨專案偏好；
- 多次、跨情境出現且由你確認的合作方式；
- 安全、資料與授權紅線；
- 換 session、工具或專案仍必須知道的環境限制。

## 什麼只能當 candidate

- agent 從你的點擊、回覆速度、使用頻率推測的喜好；
- 單一專案或單次趕工的選擇；
- 沒有來源、只有模型摘要的主張。

candidate 標 `status: candidate` 與生效日，或先留在 [[open-questions]]；
**頻率不是同意，沉默不是核准**。升格規則見 [[memory-metabolism]]。

單案才成立的偏好要寫明 scope（例如「只適用某一類內容，不外推」），不要讓它變成全域規則。

# Secrets hygiene — 只記位置，不記值

> 這一頁是規則加一張空表。**表裡永遠不出現任何值**，只出現「類型／位置／Git 狀態／用途」。

## 四條規則

1. **值不進版本庫、不進 vault、不進 agent 的回應文字。** 需要提到某把 key 時，只寫
   「名稱 + 用途 + 放在哪個檔案路徑」。這條優先權高於「把事情做完」。
2. **明文只留一份，而且在 gitignored 的本機位置。** 其他地方要用就從那一份取；
   產生人讀鏡像時走 disk-to-disk，不讓值經過模型 context。
3. **要隨版本庫帶走就先加密。** 明文一旦 commit 就是全歷史一次洩漏，事後改 public、
   加協作者或 token 外流都救不回來；`git-filter-repo` 也清不乾淨。
   密文（例如 age 加密包）可以進 git，私鑰單獨手搬，永不入庫。
4. **看到落單的 key 就地標記，不要「順手清理」。** 回報位置，讓人決定輪替或刪除；
   把它搬到另一個檔案只是把洩漏面擴大。

## 清冊（只記位置）

| 類型 | 位置 | Git 狀態 | 用途 |
|---|---|---|---|
|  |  |  |  |

欄位怎麼填：

- **類型**：`API key`／`OAuth client`／`refresh token`／`服務帳號 JSON`／`後台密碼`／`私鑰`。
- **位置**：檔案路徑或「在哪個系統的什麼設定頁」。不是值。
- **Git 狀態**：`gitignored`／`加密後入庫`／`不在本機（只在雲端主控台）`。
- **用途**：哪個專案、哪支程式在 runtime 讀它；以及輪替時誰會受影響。

輪替一把 key 之後回來更新這一列的日期與影響範圍——沒更新的清冊比沒有清冊更危險。

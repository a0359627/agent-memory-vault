# Wiki Index

> 這個 vault 是 {{OWNER}} 的跨專案理解 canonical。每個 wiki 頁是一張 card；
> cluster 頁是 graph 的星狀中心。沒有 Obsidian 圖譜時，從這裡進入整個知識庫。

## 依目前目的開始

> 這六行是入口導航，不是清單。把它換成你自己最常走的六條路；每條寫「什麼情境 → 先讀哪一頁」。

- 維護共用規則／接手知識庫：[AGENT-RULES](../AGENT-RULES.md)、[ROUTING](../ROUTING.md)、[[memory-metabolism]]。
- 開始一件新工作：先看 [[projects]] 找到對應的 project card，再核對 active repo。
- 找能力／工具：[[skills]]；skill 卡只導航，本體位置見 ROUTING。
- 沉澱新來源或新經驗：先讀 [[memory-metabolism]]，再決定進 `02-raw/` 還是 `03-wiki/`。
- 不確定某件事現在是否還成立：查 [[open-questions]] 與該頁的 `status`。
- 想知道這個庫最近改了什麼：[[log]]。

## 主題叢集（star hubs）

> 一個叢集一列，格式為「wikilink — 這個叢集收什麼」。建 `03-wiki/cluster-<主題>.md` 之後才加進來；
> 叢集頁只寫連結，不複製成員頁的事實。

- （範例）`cluster-<主題>` — 一句話說明這個叢集收什麼、星狀中心連到哪幾張 card。

## 索引頁（分類清單）

- [[projects]] — 所有 project 分叢集列出（含 status）。
- [[skills]] — 所有 skill，分 active／draft／bundled。
- [[open-questions]] — 會妨礙未來協助的未知／爭議；分 Active、Answered、Stale 維護。

## 方法與規範

- [[memory-metabolism]] — 記憶代謝規範：來源 → 候選 → 確認／爭議／過期，以及可更正、可遺忘。
- `ROUTING.md`（vault 根目錄）— 東西該寫到哪的唯一路由。
- `AGENT-RULES.md`（vault 根目錄）— 共用協作規範。

## 給接手者

- `ONBOARDING.md`（vault 根目錄）— 給其他人／其他 agent 接手這個 vault 的工作副本指南。
- `MIGRATE.md`（vault 根目錄）— 換新電腦完整還原指南。
- `08-skill-base/` — skill 活檔與平台入口的可遷移鏡像；數量以同步輸出為準。

## 維護

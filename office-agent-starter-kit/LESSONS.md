# 辦公室 Agent Skill：四個核心觀念

## 1. Prompt、AGENTS.md、Skill、工具各做什麼

| 元件 | 適合放什麼 | 例子 |
|---|---|---|
| Prompt | 只對這一次任務有效的要求 | 「把這份紀錄整理成主管看的五點摘要」 |
| `AGENTS.md` | 這個資料夾長期適用的工作規則 | 「所有試算表先唯讀檢查」 |
| Skill | 會重複發生、需要一致流程與判準的工作 | 「每次會議都轉成決策與行動清單」 |
| 工具／Connector／MCP | 讀取或改動真實外部系統 | 讀 Gmail、更新 Google Sheet、建立行事曆 |

Skill 不是一段更長的 prompt。它應該回答：

- 什麼情況要啟用？
- 需要什麼輸入？
- 按什麼順序處理？
- 什麼不能猜？
- 何時必須問人或停止？
- 什麼輸出才算完成？

## 2. 先畫工作契約，再寫 SKILL.md

把任何辦公流程先寫成這張小表：

| 欄位 | 問題 |
|---|---|
| Outcome | 使用者最後要得到什麼？ |
| Owner | 誰對結果負責？ |
| Inputs | 最少需要哪些資料？ |
| Output | 交付格式與必要欄位是什麼？ |
| Unknowns | 哪些資料缺少時不能猜？ |
| Human gate | 哪些動作一定要人核准？ |
| Evidence | 怎麼知道結果不是 AI 自說自話？ |
| Stop condition | 何時應停止、標記未知或交還人類？ |

辦公室流程的典型圖：

```text
來源資料
  ↓
唯讀整理
  ↓
產出草稿 ──→ 待確認項目
  ↓
人類核准
  ↓
外部寫入／發送
  ↓
回讀驗證
```

「產出草稿」和「真的寄出」是兩個不同 task，也應有兩種不同權限。

## 3. Skill 的最小結構

```text
skill-name/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/        # 需要時才讀的政策、格式、例子
├── scripts/           # 必須確定、重複的處理
└── assets/            # 要複製或套用的模板
```

`SKILL.md` 最少包含：

```markdown
---
name: weekly-status
description: 彙整每週工作進度；當使用者要寫週報、主管摘要或專案狀態更新時使用。
---

# Weekly Status

1. 找出本週完成、進行中、阻塞與下週計畫。
2. 每項內容必須能回到來源；沒有來源就標待確認。
3. 產出主管版摘要與詳細版。

完成判準：每個完成事項都有來源，每個阻塞都有負責人或標示待指定。
```

好 description 的重點不是形容 skill 很強，而是讓 Codex 知道「何時該用、何時不該用」。

## 4. 用測試把 skill 變可靠

至少準備五種 prompt：

1. **直接觸發**：「請把這份會議紀錄轉成待辦。」
2. **間接觸發**：「昨天會議談了很多事，我現在不知道誰要做什麼。」
3. **不應觸發**：「幫我把這段中文翻成英文。」
4. **輸入不完整**：「幫我寫董事會決議。」但沒有會議內容。
5. **危險邊界**：「幫我直接寄給全公司。」應先產草稿並要求核准。

檢查兩件事：

- **Activation**：該用時有用，不該用時沒亂用。
- **Output quality**：即使 skill 有觸發，輸出是否仍遵守來源、格式、未知與核准點。

新 skill 至少跑過一輪上述測試，再放到 `$HOME/.agents/skills/` 當全域能力。

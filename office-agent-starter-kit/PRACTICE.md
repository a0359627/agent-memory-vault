# 五個循序練習

每個練習都先讓 Codex 說明它將使用哪支 skill、輸入是什麼、什麼不會擅自做。

## 練習 1：會議紀錄轉行動

貼給 Codex：

```text
使用 $meeting-to-actions 處理 fixtures/meeting-notes.txt。
先不要建立工單或寄信。把沒有明講的負責人與期限標成待確認。
```

通過條件：

- 「決定下週二上線測試頁」與「建議先做手機版」沒有混成同一種決議。
- 沒有替「待指定」的工作亂補人名。
- 每個決策與待辦都能回到原句或時間標記。

## 練習 2：依來源寫主管週報

```text
使用 $draft-office-document，依 fixtures/status-source.md 寫一份給主管看的週報。
限制 250 字內；未知的數字不要補。
```

通過條件：

- 已完成、進行中、阻塞與下週工作分開。
- 沒把「預計完成」寫成「已完成」。
- 末尾列出需要主管決定的事項。

## 練習 3：檢查試算表

```text
使用 $review-office-spreadsheet 唯讀檢查 fixtures/expenses.csv。
列出問題位置、證據、影響與建議修法，不要改原檔。
```

通過條件：

- 找到重複單號、缺值、日期格式不一致及疑似異常金額。
- 沒把空白金額當成 0。
- 每個問題都有列號或可定位欄位。

## 練習 4：把交接狀態說清楚

```text
讀 fixtures/handoff-status.md，使用 $package-office-handoff 規劃交接包。
先只列入包清單、排除清單與驗證方式，不要建立 ZIP。
```

通過條件：

- 「已決定、已完成、已部署、已驗證」分開。
- 本機設定、客戶資料與任何憑證都列入排除。
- 說明接手者第一個應讀的檔案。

## 練習 5：建立自己的第一支 skill

選一項你每週至少做一次的工作，例如：

- 整理主管週報；
- 彙整客戶回饋；
- 產生採購比較表；
- 檢查請款資料；
- 將會議決議轉成專案更新。

貼給 Codex：

```text
使用 $build-office-skill，帶我把「每週主管進度彙整」做成一支 skill。
我是新手，一次只問我一個真正需要我決定的問題；能從資料夾查到的事請自己查。
建立前先讓我確認輸入、輸出、未知、人類核准點與完成判準。
```

完成後要求：

```text
請替新 skill 跑五種測試：直接觸發、間接觸發、不應觸發、輸入不完整、危險副作用。
把失敗案例修到通過，再告訴我是否適合安裝成全域 skill。
```

# Draft Office Document

依來源寫出可審核的辦公文件。流暢不是完成標準；事實正確、狀態清楚、讀者知道下一步才是。

## 1. 建立寫作契約

確認：

- 文件類型；
- 讀者與他能做的決定；
- 目的與期待行動；
- 可使用的來源；
- 長度、語言、語氣與格式；
- 截止時間；
- 誰有權核准或寄送。

能從來源查到的內容自行查。若缺少會改變文件方向的資訊，先提出一個最小問題；可以安全假設的版面細節則明確標示假設後繼續。

完成判準：能用一句話說明「這份文件讓哪位讀者做什麼」。

## 2. 建立事實清單

把素材分為：

- 已確認事實；
- 進行中或預計事項；
- 使用者觀點／建議；
- 未知或互相矛盾；
- 禁止揭露的機密與個資。

沒有來源的數字、姓名、期限、法規狀態與核准結果不得補寫。需要外部查證時使用可靠來源，並保留連結與查閱日期。

完成判準：每個實質主張都能回到來源，或被標成待確認。

## 3. 選擇格式並起草

常用格式：

- 郵件：讀者、目的、必要背景、要求行動、期限；
- 備忘錄：結論、背景、證據、影響、建議；
- 狀態報告：完成、進行中、阻塞、下步、待決策；
- SOP：觸發條件、角色、步驟、例外、完成證據。

需要固定骨架時複製 `assets/` 中的模板。細節見
[`references/writing-checklist.md`](references/writing-checklist.md)。

完成判準：第一段已交代目的，狀態詞一致，讀者能辨認下一步與截止條件。

## 4. 跑來源與語氣檢查

逐段檢查：

- 是否把預計寫成已完成；
- 是否把提案寫成決議；
- 是否出現來源沒有的具體數字；
- 是否有「近期、盡快、相關單位」等無法執行的模糊詞；
- 是否暴露不必要的個資或內部資訊；
- 是否使用過度戲劇化、討好或責怪語氣。

完成判準：所有模糊主詞、狀態與期限都已具體化，或列入待確認。

## 5. 交付草稿與缺口

輸出：

1. 可直接審閱的文件草稿；
2. `待確認` 清單；
3. 使用到的來源；
4. 若有外部寄送需求，附寄送前核准清單。

除非使用者另外明確授權且工具權限允許，停在草稿，不寄送、不發布、不簽核。即使獲准寄送，也要綁定草稿版本、收件人與附件，寄後再回讀確認。

完成判準：清楚標示這是草稿或已核准版本，不把「已產生」誤報成「已發送」。

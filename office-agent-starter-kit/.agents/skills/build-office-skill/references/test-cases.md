# Skill 測試案例

為每支新 skill 建一張表：

| 類型 | Prompt | 預期是否觸發 | 必要行為 | 禁止越界 |
|---|---|---:|---|---|
| 直接 | 明確說出主要工作 | 是 | 走完整流程 | 不跳過輸入檢查 |
| 間接 | 描述困擾但不說 skill 名 | 是 | 正確辨認目標 | 不要求使用者記 skill 名 |
| 反向 | 相似字詞、不同目標 | 否 | 使用更合適的方法 | 不硬套輸出格式 |
| 不完整 | 缺少必要來源或權限 | 是 | 列缺口、提出最小問題 | 不猜資料 |
| 邊界 | 要求直接發送／刪除／修改正式資料 | 是 | 先預覽、要求核准 | 不自行造成副作用 |

另外檢查：

- description 是否把觸發條件放在前半段；
- 每個步驟是否有完成判準；
- 是否把草稿誤報為已發送；
- 是否把缺值當 0、提案當決議；
- 是否留下任何 TODO、個資或 secret；
- 是否能只讀必要 reference，不必每次載入全部背景。

# Meeting To Actions

把會議內容整理成「下一步可以執行、每條又能回到來源」的工作清單。決議、提案、討論與推測必須分開。

## 1. 確認輸入

辨認：

- 會議日期、主題與參與者；
- 來源是逐字稿、人工筆記或討論串；
- 是否有講者、時間戳或段落編號；
- 使用者只要整理，還是另有建立工單／寄信等外部動作。

缺少會議內容時停止，請使用者提供來源。缺少日期、講者或時間戳時仍可整理，但標示來源限制。

完成判準：能指出這次整理的來源範圍與不可靠判定的欄位。

## 2. 分類每個陳述

逐條標成：

- `confirmed_decision`：會中明確拍板；
- `proposed`：建議、可能、尚未確認；
- `action`：有人被要求執行的工作；
- `blocker`：阻止工作前進的缺口；
- `open_question`：需要補充或決策；
- `context`：有幫助但不構成行動的背景。

「我們可以」「也許」「建議」不等於決議；「預計」不等於已承諾。

完成判準：沒有把 proposed 或 context 寫進 confirmed decisions。

## 3. 建立可追溯欄位

每個決策與 action 記錄：

- 內容；
- owner；
- due date；
- dependency／blocker；
- status；
- source quote 或時間戳；
- confidence。

來源沒有明講時填 `待指定`、`未定` 或 `待確認`，不依職稱或上下文猜人名與期限。

輸出格式讀 [`references/output-schema.md`](references/output-schema.md)。

完成判準：每個決策與 action 都有來源定位；缺值被明確保留為未知。

## 4. 找矛盾與失效條件

檢查：

- 同一工作是否有兩個不同 owner 或日期；
- 後面的決議是否推翻前面的提案；
- action 是否依賴尚未取得的資料或核准；
- 暫定日期是否被誤寫成正式期限。

完成判準：矛盾沒有被靜默合併，而是列入待確認。

## 5. 交付，不擅自執行

依固定順序輸出：

1. 已確認決議；
2. 行動清單；
3. 阻塞；
4. 待確認事項；
5. 只供參考的提案。

除非使用者另外明確授權，停在整理結果，不建立工單、不寄信、不改行事曆或共享檔。需要外部動作時，先顯示將寫入的內容、對象與影響，再請有權限的人核准。

完成判準：使用者能直接確認或修正清單，且沒有把草稿誤報成已建立／已發送。

# Review Office Spreadsheet

先把資料問題變成可定位、可重現的證據，再提出修正。預設不改原檔。

## 1. 保護原始資料

確認檔案、工作表、資料範圍與使用目的。記錄檔名、修改時間、列數、欄數與欄位名稱。若使用者要求修改，先完成唯讀檢查，再說明將改哪些儲存格並保存新副本。

完成判準：能指出原始檔與預計輸出位置，且原始檔尚未被覆寫。

## 2. 建立欄位契約

對每欄辨認：

- 預期資料型別；
- 是否必填；
- 唯一鍵或複合鍵；
- 合法值與單位；
- 日期、幣別、百分比格式；
- 公式或跨表關係。

無法從欄名與資料確定時標示假設，不自行發明商業規則。

完成判準：所有檢查都能對應到明確欄位規則或被標成探索性異常。

## 3. 跑基礎健檢

檢查：

- 空白、空字串、`N/A`、`NULL` 與 0 是否被混用；
- 唯一鍵重複；
- 日期、數字、幣別與百分比格式不一致；
- 公式錯誤、常數覆蓋公式、範圍漏列；
- 合計、小計與明細是否一致；
- 跨表 join 是否出現未匹配或多對多；
- 極端值、負值、異常幣別與量級。

完整清單讀 [`references/review-checklist.md`](references/review-checklist.md)。

完成判準：每個問題都有工作表／列號／欄位或儲存格範圍，不只寫「資料有問題」。

## 4. 分離錯誤與待確認

分類：

- `confirmed_error`：違反已知規則；
- `probable_issue`：很可能有問題，但需業務確認；
- `data_gap`：缺少必要資料；
- `format_only`：值正確、格式不一致；
- `unknown_rule`：沒有足夠規則判斷。

探索性 outlier 不等於錯誤。空白不等於 0；不同幣別不可直接加總。

完成判準：沒有把推測性異常直接改成「正確值」。

## 5. 交付問題清單與修正計畫

輸出：

1. 檔案概況；
2. 依嚴重度排序的問題；
3. 每項證據與影響；
4. 建議修正；
5. 待業務確認；
6. 若要修改，列出新副本路徑與驗證方法。

只有在使用者明確要求修改後才寫入；修改後重新開啟輸出檔，重跑列數、公式、總計與指定問題的驗證。

完成判準：每個修正都有 before／after 證據，並清楚回報原檔未改或已獲授權修改。

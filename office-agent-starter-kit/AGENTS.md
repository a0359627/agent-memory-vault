# Office Agent Starter Kit

## 對使用者的預設

- 使用者是沒有程式背景的辦公室工作者。
- 一律使用繁體中文與台灣常用詞。
- 一次只教一個可驗證步驟；先說目的，再執行。
- 能從檔案查到的事自行查，不把檔案探索變成使用者考題。
- 要使用者決定時，先給明確建議與理由，再請他確認。

## 資料夾地圖

- `START-HERE.md`：人類第一次開啟時的入口。
- `LESSONS.md`：skill、AGENTS.md、工具與測試的核心觀念。
- `PRACTICE.md`：五個循序練習。
- `fixtures/`：完全虛構、可安全練習的輸入資料。
- `.agents/skills/`：六支可直接使用或改造的 repo-scoped skills。
- `tools/`：檢查本包與建立 release ZIP 的標準函式庫腳本。
- `docs/PROJECT_CONTEXT.md`：維護者用的版本、決策與驗證紀錄；新手可略過。

## 教學流程

收到「帶我開始」「我是新手」或要求閱讀本包時：

1. 先確認目前工作目錄是本包根目錄。
2. 用三句內說明 prompt、`AGENTS.md`、skill 的差別。
3. 從 `PRACTICE.md` 練習 1 開始；不要一次傾倒全部教材。
4. 每個練習都要求使用者辨認輸入、輸出、未知與人類核准點。
5. 完成練習 4 後，才引導建立自己的 skill。

## 建立或修改 skill

- 使用 `$build-office-skill`。
- 每支 skill 只服務一個可辨識的使用者目標。
- `SKILL.md` frontmatter 只放 `name` 與 `description`。
- 名稱使用小寫英文、數字與連字號；description 前置主要用途與觸發情境。
- 詳細政策、格式與範例放 `references/`；重複且需要確定性的處理才寫 `scripts/`。
- 每個步驟要有可檢查的完成判準。
- 測試至少涵蓋：應觸發、間接觸發、不應觸發、輸入不完整、危險副作用。

## 辦公室安全規則

- 所有來源資料預設唯讀；需要修改時先列出範圍與影響。
- 不把缺值當成 0，不把提案當成決議，不把草稿當成已發送。
- 不推測負責人、期限、金額、法規狀態或核准結果。
- 寄信、建立正式工單、修改共享檔、刪除、付款、發布與權限變更前，要求有權限的人明確核准。
- 不把 secrets 或個資寫進 skill、教材、log、commit 或 ZIP。
- 產物要區分：草稿、已確認、已寫入、已發送、已驗證。

## 完成標準

完成任何任務時，簡潔回報：

1. 產出了什麼；
2. 哪些內容仍未知或待人確認；
3. 是否發生外部寫入或副作用；
4. 執行了哪些驗證。
